| **T04 fix round 2 RESOLVED** the all-`Skip` symptom logged in the T06 entry and the fix-round-1 entry above. Root cause was that the direct `Setup.Get(0)` call in round 1, though no longer denied by table-level permission indirection, could still raise an uncaught error under the restricted DemoPortal test-session user (missing/undiagnosable from the CLI) and an uncaught error inside `OnBeforeTestMethodRun`/`OnAfterTestMethodRun` causes the platform to skip the test rather than fail it — so any residual error in the hook body, from any cause, produced the identical 9/9-Skip symptom. Fix: hooks now never throw. `MUT Mut` gained `LastHookError: Text` plus `SetLastHookError`/`GetLastHookError` (and `Reset()` clears it); `MUT Test Hooks` wraps the setup read in a new `[TryFunction] local procedure TryReadActiveMutant(var ActiveMutantId: Integer; var RunNo: Integer)` (read-only — no writes, per the TryFunction rule) and both subscribers now branch on its result, recording `'Before '/'After ' + FunctionName + ': ' + GetLastErrorText()` via `MutationCore.SetLastHookError(...)` instead of letting any error propagate; the `MUT Mutant Result` insert in the after-hook is intentionally left unwrapped (an insert failure there is expected to surface as an ordinary test failure, which is acceptable).
